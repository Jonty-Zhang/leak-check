# AI 味清单（学术文体版）

`scan_leaks.py` 的 `STYLE_*` 规则按这份清单查。标准是论文、课程报告、实验报告的文体，不是散文：不追求"有个性""多用我"，只去掉一眼就像机器写的套路。

总原则：

- **单独一处不算问题，满篇都是才是。** 所以脚本全部只报 WARN，按全文出现次数和篇幅给阈值（篇幅越长，允许的次数越多），同一类合成一条，列出所有位置。只有让步式自贬和结尾的空洞展望出现一次就报。
- **AI 味不是硬伤。** 报告里放在"建议看看"，不放"必须改"。
- **改的时候只动套话本身。** 不改观点，不调结构，不补新内容。套话背后如果本来就没有具体内容，就删掉，不要编一个"具体内容"顶上去。

脚本阈值（约 N 字的正文，N 只算正文段落里的汉字，不算标题、表格、题注、代码、参考文献；正文少于 200 字不查）：

| 代码 | 查什么 | 什么时候报 |
|---|---|---|
| STYLE_WORD | 套话词 | 全文 ≥ 4 + 3×N/10000 处 |
| STYLE_SUMUP | 综上所述 / 总而言之 / 总之 / 总的来说 | 全文 ≥ 2 + N/10000 处 |
| STYLE_TRIAD | 三段式排比 | 全文 ≥ 3 + 2×N/10000 处 |
| STYLE_ELEVATE | 节末升华句 | 至少 2 个小节、且不少于小节数的 1/4 以升华句收尾 |
| STYLE_CONCEDE | 让步式自贬 | 出现就报 |
| STYLE_DASH | 破折号 | 全文 ≥ 4 + 2×N/10000 处 |
| STYLE_ENDING | 空洞的乐观结尾 | 正文最后三段里出现就报 |

用 `--no-style` 关掉整类，用 `--ignore STYLE_DASH` 之类关掉单项。

---

## 1. 套话词（STYLE_WORD）

| 词 | 改法 |
|---|---|
| 至关重要、举足轻重、不可或缺、不可忽视 | 说清楚为什么重要（"占总能耗的 40%"），说不出就删 |
| 深入探讨、深入研究、深入分析、深度剖析 | "分析""研究"就够了 |
| 赋能、助力、抓手 | 删，或换成实际动作："赋能教学" → "用于课堂签到" |
| 彰显、凸显、标志着 | 删掉夸大意义的半句 |
| 具有重要（现实/理论）意义、意义重大 | 说出意义是什么；说不出就删 |
| 奠定了坚实基础、提供了有力支撑 | 写具体结果："为第 4 章的参数选择提供了初值" |
| 发挥着重要作用、扮演着关键角色 | 写它做了什么 |
| 值得注意的是、需要指出的是、不难发现 | 直接说那件事 |
| 众所周知、毋庸置疑、不言而喻、显而易见 | 删。真的显然就不用说，不显然就要论证 |
| 全方位、多维度、多层次、深度融合、有机结合 | 列出实际涵盖的方面 |
| 新篇章、新高度、注入新活力、画卷、宏伟蓝图 | 删 |
| 不仅是……更是…… | 拆成两句陈述，或只留有内容的那半 |
| 段首"此外，""另外，""与此同时，" | 大多可以直接删，句间关系靠内容体现 |

**什么时候没问题：**

- 讨论具体对象时的正常用法："温度对反应速率至关重要，见表 2"后面跟了数据，偶尔一次不算。脚本按频次报，就是为了不抓单次。
- 引文、政策原文、访谈原话里的这些词。
- "闭环控制""开环与闭环"等专业术语，脚本不查"闭环"。

## 2. "综上所述"泛滥（STYLE_SUMUP）

一篇论文一般只在结论开头用一次。每节末尾都来一句"综上所述"，就是 AI 的段落模板。

- 改法：保留结论开头那一处，其余删掉这几个字，句子直接从内容开始。
- **没问题的情况**：题目解析、习题答案里"综上所述，答案为 B"是解题格式。脚本跳过含"答案、选项、取值范围、等号"的句子；全文有 3 处以上"【解析】""故选""故答案为"的题解类文档，整篇不查这一项。

## 3. 三段式排比（STYLE_TRIAD）

| 模式 | 例子 |
|---|---|
| 三个评价性形容词并列 | 高效、稳定、可靠；更加便捷、更加准确、更加及时 |
| 同一个词起头重复三次 | 提升了效率，提升了速度，提升了科学性 |
| 三个"动词 + 了"并列（心得体会的常见句式） | 锻炼了动手能力，培养了团队意识，加深了理论理解 |

- 改法：实际只有两项就写两项；每一项都成立，就各给一个具体内容或数值（"响应时间 0.3 s，连续运行 72 小时无掉线"）。
- **没问题的情况**：具体名词的并列（"电阻、电容、电感"、"实验一、实验二、实验三"）。脚本只认评价性形容词和固定起头词，不查名词列表。

## 4. 节末升华句（STYLE_ELEVATE）

每一节讲完都要拔高一句："这一设计充分彰显了……的巨大潜力""为……奠定了坚实基础""具有重要的现实意义"。

- 改法：删掉。一节讲完就停；意义留到结论里，具体地写一次。
- 脚本只看每个小节最后一段的最后一句，跳过标题含"结论、总结、结语、小结、展望、心得、体会、收获、反思、摘要"的小节（这些小节谈意义是本分）。
- **没问题的情况**：心得体会、答辩稿、演讲稿这类文体本来就允许收尾表态，WARN 可以按文体排除。

## 5. 让步式自贬（STYLE_CONCEDE）

先说别的方法更好，再说自己为了省事选了差的；或者自谦套话。读者读到的是"作者知道自己做得不对"。

| 原句 | 改法 |
|---|---|
| 更好的做法是使用 X，但为了简便本文采用 Y | 本文采用 Y，原因是……（正面写理由：数据量、课程范围、成本、可解释性） |
| 理想情况下应当……，但限于时间只做了…… | 本文完成了……；确有未完成的，放到"不足与展望"写一次 |
| 严格来说应该……，这里只做了近似 | 取……近似，误差在……以内 |
| 这种方法虽然简单，但…… | 直接说这种方法的作用 |
| 本人水平有限，难免存在疏漏 / 时间仓促 / 恳请批评指正 | 整句删 |

- 修的时候**不改选择本身**：原文用的是 Y，改完还是 Y，只是换成正面陈述。理由原文没写的，不要替作者编一个，列进"需要你确认"，问作者为什么选 Y。
- **没问题的情况**：数学推导里"为简便起见，记 a = …"是记号约定，脚本不查单独的"为简便起见"。书籍前言里的"水平所限，敬请指正"是体例，学生作业里才算问题。

## 6. 破折号连用（STYLE_DASH）

用"——"制造停顿和节奏，一段里好几个，是 AI 的典型写法。

- 改法：大多数改成逗号、冒号或句号；全文留两三处真正需要插入说明的。
- 脚本只数至少一侧是中文的破折号，不数"1990—2000 年""3—5 页"这类范围，也不数方程式里当箭头用的"——"。
- **没问题的情况**：副标题（"××研究——以××为例"）、引文原有的破折号。

## 7. 空洞的乐观结尾（STYLE_ENDING）

全文最后几句是"展望未来，……必将迈向新的高度""前景广阔，未来可期""相信在……的共同努力下"。

- 改法：换成下一步具体要做的事（"下一步在 20 间宿舍扩大采样，并加入温度数据"）。原文没有具体计划的，就删掉这句，不要编一个计划。
- **没问题的情况**：演讲稿、答辩稿结尾的致谢和表态。

## 脚本查不出的（通读时看）

- 每段都是"总起句 + 三个并列 + 总结句"的固定结构。
- 所有句子长度差不多，读起来像念稿。
- 列表项全是"**加粗小标题：** 解释"。
- 章节开头"在本章中，我们将……"、结尾"本章介绍了……"，每章都有。
- 模糊归因："研究表明""专家认为""业界普遍认为"后面没有文献。
- 换到任何一篇报告里都成立的句子（没有信息量）。

这些在通读时按 `semantic-checklist.md` 的 D 节判断，同样只放"建议看看"。
