# 雷点与硬伤清单

`scan_leaks.py` 按这份清单查字符串和结构；脚本查不出的变体，通读时照这份清单的思路去找。每一类都写了**什么时候其实没问题**，判断 WARN 和疑似误报时用。

总原则：成品的读者是老师或评审，作者是学生本人。任何一句话如果暴露了"这是按指令生成的""这是还没收尾的草稿""这是聊天记录"，就是雷。

---

## 一、雷点：一眼看出是 AI 代写或没收尾

### 1. 元话语（META）：转述了下指令的人

| 原句 | 问题 | 改法 |
|---|---|---|
| 根据用户的要求，本文采用问卷调查法…… | 报告里没有"用户" | 本文采用问卷调查法…… |
| 用户说希望重点分析熬夜原因。 | 复述聊天记录 | 本文重点分析熬夜的原因。 |
| 由于用户未提供原始数据，本文假设…… | 把缺材料的事写进正文 | 本文假设……（缺数据这件事告诉作者，不写进正文） |
| 根据你提供的资料 / 按照您的要求 | 在对读者说话 | 删掉这半句 |
| 老师要求本文不少于 3000 字 | 读者就是老师 | 删掉 |
| 根据课程要求 / 题目要求我们分析…… | 读起来像在交差 | 本文分析…… |
| 本文共计 3200 字 / 已满足全部要求 | 自证达标 | 删掉 |
| 上一轮对话中提到 / 根据你的提问 | 提到对话过程 | 删掉 |

**什么时候没问题：**
- **"用户"是研究对象**：需求分析、产品设计、人机交互、软件工程类文章里，"用户希望按价格筛选""目标用户是大学生"都是正常写法。脚本在全文有 3 段以上把"用户"当领域词用时，会把"用户……"类命中降为 WARN。但如果同一句话还提到了报告或论文本身，比如"用户说这一节要写详细，所以本报告分三点展开"，仍然报 ERROR。
- **心得、反思、课程总结**：有时会叙述课堂经历，比如"老师让我们每组做一个原型"。这是在写事件，不是在转述要求，可以保留。
- **大模型相关论文**：里面的"提示词 / prompt"是术语。
- **引用原话**：比如访谈记录里的引文。

### 2. 草稿残留（DRAFT）：写作过程的备注没删

| 原句 | 改法 |
|---|---|
| 之后要替换掉这里的内容。 | 删掉备注；同时检查它指的那段内容是不是临时写的，是就要补真实内容 |
| 此处插入实验流程图。/ 这里放截图 | 有图就插图、配图题；没图就删掉这句，并告诉作者缺哪张图 |
| 【此处填写结论】 / [插入图片] / （此处为……） | 补内容；补不了就告诉作者 |
| TODO / TBD / FIXME / 待补充 / 待确认 / （待定） | 同上 |
| 学号：XXX / 姓名：____ / ×× 大学 | 填上真实信息，或者告诉作者要填 |
| 请根据实际情况修改 / 请替换为你的数据 | 这是写给作者看的说明，删掉 |
| （略）/ 其余同理 / 剩下的代码类似 | 写完整 |
| 以下数据为示例 / 虚构数据 | 换成真实数据，或者告诉作者这里没有真实数据 |

**什么时候没问题：**
- "待定系数法"、受力分析里的"方向待定"是学科用语。脚本只认括号里的"（待定）"。
- "限于篇幅，此处省略推导，详见文献[3]"写明了出处，是论文的正常写法。
- "后续工作需要补充更多数据"写在展望里，是在讲研究计划，不是草稿备注。
- "某某公司""张三"出现在举例中可以；出现在封面或作者信息里，就是没填的空。

### 3. 版本标记（VERSION）：改稿的痕迹

| 原句 | 改法 |
|---|---|
| 标题写成"改进版""最终版论文""（修订版）" | 删掉版本字样，用真正的标题 |
| 以下是改进版： / 这是最终版 | 删掉整句 |
| 修改前：…… 修改后：…… | 只留改后的正文 |
| （已修改）（新增）【已润色】 | 删掉标注 |

**什么时候没问题：** "改进版 A* 算法"是方法名；参考文献里的"（第 2 版）"是版次信息。脚本会跳过参考文献表，也不报"改进版 + 名词"的写法。

### 4. 对话残留（CHAT）和 AI 自曝（AI）

| 原句 | 改法 |
|---|---|
| 好的，以下是根据你的要求修改后的论文。 | 整句删掉 |
| 希望对你有帮助！如果还需要调整请告诉我。 | 整句删掉 |
| 你可以根据需要调整 / 需要我再帮你…… | 整句删掉 |
| 作为一个 AI 语言模型 / 我无法访问该网站 | 整句删掉 |
| Here is the revised version / I hope this helps / as an AI | 整句删掉 |
| 以下是 / 下面是（段首） | WARN：论文里一般直接写内容；讲义、教程里"下面是完整代码"可以保留 |

### 5. 格式残留（MD）：Markdown 或 LaTeX 源码没转换

- Word 或 PDF 里出现 `## 标题`、`**加粗**`、反引号、`| 表格 |`、`---`、`[文字](链接)`、`$E=mc^2$`、`\frac`。
- 改法：转成真正的标题样式、字体加粗、原生表格、Word 公式。
- `.md` 文件本身就是 Markdown，不查这一类。txt 里只报 WARN。
- **没问题的情况**：讲表达式求值、运算符的讲义里，段首的 `#`、`+`、`*` 是正文内容。脚本不查表格单元格，列表符号只报 WARN。

### 6. Word 残留（DOCX）

| 问题 | 处理 |
|---|---|
| 还有批注 | 先看批注内容，里面可能是老师或同学的意见；处理完再删 |
| 还有未接受的修订 | 别人一打开就是满屏红字。逐条看过后接受或拒绝 |
| 荧光高亮 | 改稿时常用来标"待改"。确认改完后去掉 |
| 隐藏文字 | 打开"显示隐藏文字"就会露出来 |

## 二、硬伤：一眼不对

| 代码 | 例子 | 处理 |
|---|---|---|
| BROKEN_FIELD | "错误！未找到引用源。" | Word 交叉引用断了。重新插入引用，或者全选后按 F9 更新域 |
| BROKEN_MARK | `[引用]`、`[?]`、PDF 里的"图 ??" | 补上真实的引用；找不到出处，就删掉依赖这条引用的话 |
| NUM_CAPTION | 图 1、图 3，没有图 2；有两个表 2 | 重新编号，**同时改正文里所有引用了这些编号的地方** |
| NUM_FIGREF | 正文写"如图 5 所示"，但没有图 5 | 改成正确的编号，或者补上这张图 |
| NUM_HEADING | 1 引言 → 3 方法 | 重新编号 |
| CITE_RANGE | 引用了 [12]，文献表只有 10 条 | 找到正确的文献编号；找不到就删掉这处引用 |
| CITE_LIST | 文献编号跳号，或者正文有 [n] 但没有文献表 | 补齐或重排。注意：习题解析里的 [1][2] 常是填空编号，不是文献 |
| CITE_UNUSED / CITE_ORDER | 文献没被引用；没按首次出现的顺序编号 | WARN。要求 GB/T 7714 顺序编码制时要调整 |
| REF_YEAR | 文献年份比今年还晚；文献没写年份 | 年份不对基本可以断定是编造的；没写年份的要核实这条文献是否存在 |
| EMPTY_SECTION | 标题下面什么都没有 | 补内容，或者删掉标题 |
| DUP_PARA | 两段话一字不差 | 删掉重复的那段 |
| UNBALANCED | 括号不配对；引号写成两个右引号”…” | 修正 |
| COUNT_MISMATCH | "共回收问卷 200 份"和"共回收问卷 180 份" | 找出正确的数字（看原始数据），全文统一 |

## 三、不在 v1 范围内

AI 味的用词和套话不在本版范围内，比如"至关重要""赋能""综上所述"泛滥、三段式排比、空洞的升华句。这类问题现在交给 `humanizer-zh`，计划在 v2 并入。
