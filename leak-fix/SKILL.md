# leak-fix：查雷并修好

一句话：**把会露馅、一眼不对的句子改掉，别的一个字不动，改完能直接交。**

姊妹 skill `leak-check` 只出报告。两者共用 `scripts/` 和 `references/`。动手前必须读 `references/patterns.md` 和 `references/semantic-checklist.md`。

## 流程

### 1. 查

和 leak-check 一样（`<本 skill 目录>` 就是加载时给出的 Base directory）：

```bash
python3 <本 skill 目录>/scripts/scan_leaks.py 文件.docx            # 脚本扫描
python3 <本 skill 目录>/scripts/scan_leaks.py 文件.docx --dump     # 带段号的全文
```

按 `semantic-checklist.md` 通读全文，逐条判断脚本报的 ERROR 和 WARN，列出问题清单。误报不修，记进"已排除"。

### 2. 分三类处理

| 类别 | 例子 | 怎么处理 |
|---|---|---|
| **A. 确定的雷** | 元话语、对话残留、AI 自曝、版本标记、改稿对照、Markdown/LaTeX 残留 | 直接改。删掉露馅的半句或整句，调整到句子通顺 |
| **B. 要判断的硬伤** | 编号断裂、引用对不上、前后数字矛盾、引号方向反了、空章节、重复段落 | 能从文档本身或项目里的材料（数据文件、代码输出、对话里用户说过的事实）确定正确答案的，就改；确定不了的不改，列进"需要你确认" |
| **C. 缺内容** | 【此处填写结论】、此处插入流程图、TODO 补数据、学号 XXX、示例数据、"之后要替换"所指的临时内容 | 有素材（对话里、项目文件里）就照素材补；**没有素材就不补，绝不编造**，保留原位置，列进"需要你补"，写清楚缺什么、在哪 |

关于 C 类，要分清两种情况：

- 只是一条备注，正文其实已经写好了。比如"之后要替换掉这里的内容"后面跟着真实数据：这时删掉备注就行。
- 备注指向的内容本身就是临时的。比如示例数据、空的结论：这时按"缺内容"处理。

Word 残留的处理：

- **批注**：先把每条批注的内容抄进修改清单（里面可能是老师的意见），再删。
- **修订**：先在清单里概括修订的内容，再接受全部修订。用户之前说过要拒绝某些修订的，按用户说的办。
- **高亮**：确认对应的内容已经改完，再去掉。

### 3. 改

**改动原则**

- 最小改动：只动有问题的句子。不顺手润色，不改观点，不加新内容，不调结构。
- 删掉半句后，要读一遍整句，确认通顺。例如"根据用户的要求，本文采用问卷法"改成"本文采用问卷法"，而不是留下"，本文采用问卷法"。
- 重新编号图、表、标题、文献时，要同步改正文里所有引用这些编号的地方，改完再扫一遍确认对得上。
- 文献可疑但核实不了的，不删也不换，列进"需要你确认"。

**按格式改**

- **.md / .txt / .tex**：先复制一份备份 `原名.leakfix-backup.扩展名`，再用编辑工具逐处修改。
- **.docx**：用脚本改，这样能保留字体格式：
  1. 根据 `--dump` 的段号，写一个 `edits.json`（格式见 `scripts/fix_docx.py` 文件开头的说明）：
     ```json
     [
       {"para": 7, "find": "根据用户的要求，", "replace": ""},
       {"para": 3, "delete": true, "find": "好的，以下是"},
       {"para": 15, "find": "图3", "replace": "图2"},
       {"find": "（改进版）", "replace": ""}
     ]
     ```
  2. 先预演，确认每一条都命中：
     ```bash
     python3 <本 skill 目录>/scripts/fix_docx.py 文件.docx edits.json --dry-run
     ```
  3. 再正式写入，脚本会自动备份为 `文件.leakfix-backup.docx`：
     ```bash
     python3 <本 skill 目录>/scripts/fix_docx.py 文件.docx edits.json --inplace [--accept-revisions] [--remove-comments] [--clear-highlight]
     ```
  - 只要有一条没命中，脚本就整份不写入。遇到这种情况，修正 `find` 后重跑，不要绕过去。
  - 跨段落、公式里的文字，脚本改不了。这些列进"需要你手动改"，写清楚位置和改法。
  - Word 里断掉的交叉引用（"错误！未找到引用源"）：如果能确定原本指向哪张图表，就把这行字替换成正确的编号文字，并在清单里提醒用户：这里已从域改成了普通文字，以后编号变了不会自动更新。
- **.pdf**：没法直接改。先找同名的源文件（.docx / .md / .tex），找到了就改源文件；找不到就只出报告（同 leak-check），并说明原因。

### 4. 复验

```bash
python3 <本 skill 目录>/scripts/scan_leaks.py 文件
```

- ERROR 应该清零。剩下的每一条都要说明原因：要么是"需要你补"的缺内容，要么是已排除的误报。
- 把所有改过的段落再读一遍，确认句子通顺，也没有误删正文。

### 5. 交付说明

```markdown
## 修复完成：文件名

改了 N 处，备份在 `文件.leakfix-backup.docx`，复扫结果：ERROR 0 / WARN k（逐条说明见下）。

### 修改清单
| # | 位置 | 原句 | 改后 | 原因 |
|---|---|---|---|---|

### 需要你补（没有素材，没编）
- 第 21 段：结论还是占位符"【此处填写结论】"，需要你的实验结论

### 需要你确认
- 第 9 段和第 21 段的问卷数（200 / 180）不一致，没找到原始数据，没改

### 已排除
- …

### 批注原文（已删除）
- …
```

## 红线

- 编造数据、结论、文献、图片来填空。
- 改了清单以外的内容（顺手润色、改写观点）。
- 没备份就改原文件。
- 没复扫就说"修好了"。
